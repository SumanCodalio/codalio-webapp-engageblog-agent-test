# Implementation Plan: EngageBlog

## Summary
ContentReach is a blog posting and analytics platform designed for content teams. It enables users to create text and video posts, manage a central media library, and view in-depth performance metrics to optimize content reach and engagement.

## PRD gaps compensated
- **SITEMAP_PAGE_NO_AC (Admin System Settings/Reports):** Added compensated AC rows and planned the custom UI screens `AdminSystemSettings` and `AdminSystemReports` so the backend scaffolding matches the sitemap.
- **SITEMAP_PAGE_NO_AC (Admin root):** Added a compensated AC row for the Admin Dashboard overview linking to the `Admin` prototype page.
- **VAGUE_STORY_ROLE:** Normalized "content_manager" and "content_team_member" into the canonical `content_team_member` role in `_roles.yaml` and ACs.
- **DATA_MODEL_UX_MISMATCH:** Added prototype-required fields to `Post` (`category`, `read_time`) and `Video` (`format`, `size`, `resolution`, `bitrate`, `thumbnail`), plus virtual attributes mapped via Extras.

## Models (reference)

### Post
- Ownership: organization-scoped
- Key fields: title, content, status, category, read_time, published_at
- Relationships: belongsTo User, belongsTo Organization, hasMany Video, hasMany AnalyticsData

### Video
- Ownership: organization-scoped
- Key fields: title, url, duration, format, size, resolution, bitrate, thumbnail
- Relationships: belongsTo Post, belongsTo User, belongsTo Organization

### AnalyticsData
- Ownership: organization-scoped
- Key fields: event_type, event_data, recorded_at
- Relationships: belongsTo Post, belongsTo Organization

## Extras (NOT covered by blueprint — develop stage implements these by hand)

- **Post#show, Post#index:**
  - **Rule:** Needs virtual attributes `views` (integer count of AnalyticsData view events), `hasVideo` (boolean, true if videos present), `videoDuration` (sum of video durations), and `date` (formatted `published_at`) to satisfy the UI JSON contract.
  - **Where the code lives:** `server/app/models/post.rb` (virtual methods) and `server/app/serializers/post_serializer.rb`
  - **Acceptance criterion:** AC-14
- **Analytics#summary:**
  - **Rule:** A custom endpoint to aggregate content performance metrics (Total Reach, Avg Engagement Rate, Views by Date, etc.) for the Dashboard and Analytics pages.
  - **Where the code lives:** `server/app/controllers/api/analytics_controller.rb` + custom routes.
  - **Acceptance criterion:** AC-15
- **System monitoring endpoints:**
  - **Rule:** Custom endpoints for fetching system performance metrics and settings for the Admin screens.
  - **Where the code lives:** `server/app/controllers/api/admin/system_controller.rb`
  - **Acceptance criterion:** AC-16

## Implementation order (recommended stage flow)
1. **Plan** — this artifact set (YAMLs, plan, criteria, index).
2. **Develop** — phase A: `bundle exec rails rhino:blueprint` + migrations. Phase B: implement **Extras**. Phase C: wire up controllers. Phase D: write backend tests.
3. **UI / UI-Integration** — build screens listed above and vendor the design.
4. **Test** — run tests.
5. **Review** — compliance check.
